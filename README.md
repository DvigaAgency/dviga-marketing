# dviga-marketing — копия главной dviga.marketing без рантайма Tilda

Статическая копия **главной страницы** сайта агентства DVIGA (https://dviga.marketing/): тот же дизайн, тексты, изображения, адаптив и анимации, но вместо Tilda-скриптов и Tilda-стилей — собственный CSS (~1 файл) и JS (~9 КБ min, без зависимостей).

> Область работ по решению заказчика: **только главная страница** (шапка, футер и все её попапы/формы входят). Остальные страницы сайта (/about, /cases, /services, /blog, …) в копию не входят; все ссылки на них ведут на оригинальный сайт `https://dviga.marketing/...`. Англоязычная версия `en.dviga.marketing` не копируется.

## Быстрый старт

```bash
npm install
npm run build        # dist/ — готовая статика
npm run preview      # http://localhost:4173
```

Требования: Node ≥ 20. Для Lighthouse нужен установленный Google Chrome, для Playwright — `npx playwright install chromium`.

Переменные сборки: `SITE_URL` (по умолчанию `https://dviga.marketing`; используется в canonical/og/sitemap/JSON-LD), `NOINDEX=1` (добавить `noindex`, пока копия не выведена в продакшен), `OUT` (каталог вывода).

## Как это устроено

```
reference/html/home.html   выгрузка исходного HTML опубликованной главной (только чтение живого сайта)
        │   + Tilda MCP: JSON-LD и head-код страницы, проверка кастомного CSS проекта (он пуст)
        ▼
tools/build.mjs ──► tools/lib/zero.mjs      Zero-блок (396) → HTML + CSS
                    tools/lib/zero-layout.mjs   модель раскладки по брейкпоинтам 320/480/640/960/1200
                    tools/lib/sbs.mjs           keyframes пошаговых анимаций (hover/blockintoview)
                    tools/lib/components.mjs    cookie, слайдер отзывов, попапы, виджет, поиск
                    tools/lib/forms.mjs         формы (Zero-формы, t702, t708)
                    tools/lib/assets.mjs        <picture> AVIF/WebP, image-set() для фонов
        ▼
dist/  index.html (+ инлайн критический CSS) · assets/app.<hash>.css · assets/app.<hash>.js (+чанки) · img/ · video/ · fonts/
```

### Раскладка Zero-блоков (ядро замены)
Tilda хранит для каждого элемента координаты на каждом брейкпоинте (`data-field-*-res-*`) и применяет их скриптом. Копия делает то же **на этапе сборки**:

* значения каскадируются между брейкпоинтами так же, как в `tilda-zero` (текущий → более широкие → базовый);
* оси `axisx/axisy` (left/center/right, top/center/bottom), контейнеры `grid`/`window`, `valign` артборда, `height_vh` переводятся в `left/top/translate` на CSS;
* масштаб между брейкпоинтами (`upscale=window`) — **только CSS**: `--s: tan(atan2(100cqw, <R>px))` + стандартное свойство `zoom`. Ширина берётся из `cqw` (ширина без полосы прокрутки), контейнер — `container-type:inline-size` у `<main>`/`<footer>`/попапов (поэтому JS на resize не нужен);
* `line-height` у текстов округляется до целых px (`round(1.2em, 1px)`), как это делает `t396__fixElementsLineHeights`;
* CSS записей (типографика, цвета, hover) переписывается css-tree: селекторы Tilda → короткие классы, значения по умолчанию вынесены в `base.css`.

Проверка точности: `node tools/geom.mjs` сравнивает позиции и размеры всех 333 элементов с эталоном на ширинах 1440/1200/960/640/480/320 (расхождение ≤ 3 px).

### Анимации
Полная таблица — [reports/animations.md](reports/animations.md). Кратко: появление (fadein) — CSS-transition + один `IntersectionObserver`; hover/blockintoview — `@keyframes`, сгенерированные при сборке, переключение классов в JS; scroll-шаги и «пин» (в т.ч. увеличение видео в хиро) — один rAF-обработчик, «fixed» реализован через `transform` (внутри контейнера `cqw` `position:fixed` ведёт себя иначе); счётчик «50+», слайдер, drag-лента, попапы — отдельный код. Поддержан `prefers-reduced-motion`.

### Формы
Все 4 формы (две Zero-формы, «Рассчитайте стоимость» — многошаговая, виджет «Давайте подскажем») используют общий модуль `src/js/forms.js`: маска телефона `+7__________`, валидация (обязательные поля, email, телефон, согласие), состояния ошибки/успеха с теми же текстами, выбор файлов. Отправка:

```
POST /api/lead   (multipart/form-data)
  поля формы по их name (Name, Phone, Email, comment, Checkbox, File[] …)
  form  — идентификатор формы, page — URL страницы
```

Пока обработчика нет, форма на `localhost` считает отправку успешной (dev-заглушка), на других хостах показывает сообщение «Не удалось отправить заявку…». ## Развёртывание и кэширование
Статика из `dist/`. Файлы в `dist/assets/` имеют хеш в имени → отдавать с `Cache-Control: public, max-age=31536000, immutable`; HTML — `no-cache`. В `dist/_headers` лежит готовый конфиг (Cloudflare Pages / Netlify). Для nginx:

```nginx
location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
location = /index.html { add_header Cache-Control "no-cache"; }
gzip on; gzip_types text/css application/javascript image/svg+xml;   # или brotli on;
```

## Что не перенесено и почему

* **Яндекс.Метрика, calltracking, tilda-stat, виджет Tilda Upwidget/Uploadcare** — по заданию (трекинг не переносится, телефон статичный).
* **Полноэкранный fade-in всей страницы (блок t360)** — артефакт Tilda против вспышки неподготовленной вёрстки; в копии критический CSS инлайнится, а fade откладывал бы LCP.
* **Стрелки слайдера отзывов** — в оригинале они присутствуют в DOM, но скрыты (`display:none`); в копии тоже скрыты (кнопки есть в разметке с атрибутом `hidden`), слайдер листается автоплеем, свайпом и стрелками клавиатуры.
* **Поиск в шапке** (оригинал — виджет Tilda с индексом страниц сайта). В копии оверлей поиска повторяет вид и поведение, а запрос отправляется в Яндекс с `site:dviga.marketing` в новой вкладке.
* **Видео-шоурил хиро** `https://cp80604-bitrix-8.tw1.ru/showreel1.mp4` — **не удалось скачать**: хост не отвечает из сети, где выполнялась работа (оригинал на этом хосте тоже показывает спиннер). В копии на его месте чёрная скруглённая плашка, поведение (увеличение при прокрутке) работает. Чтобы подключить ролик: положить файл в `source-assets/showreel1.mp4`, выполнить `node tools/optimize-video.mjs && npm run build`.
* **Скрытый SEO-блок со списком городов**: на главной такого блока нет (он есть только на страницах услуг, которые в копию не входят) — переносить нечего.
* **Другие страницы Tilda-проекта** (в проекте 238 страниц: услуги, 113 статей блога, 62 кейса и т.д.) — вне области работ. Если они понадобятся, генератор уже универсален для Zero-блоков; нужны только обработчики блоков остальных типов.

## Решения по спорным местам

* Исходник — HTML опубликованной страницы (содержит полные `data-*` Zero-блоков); Tilda MCP использован для head-кода/JSON-LD страницы, проверки project CSS и справки по формату блоков. Данные из HTML и из браузера сверены: «побеждает то, что видно на экране» (проверка — скриншоты/геометрия).
* Шрифт Inter — те же woff2, что отдаёт Google Fonts оригиналу (латиница+кириллица, переменный), self-host, `font-display:swap`, preload обоих файлов, fallback `Inter Fallback` с `size-adjust`. Отдельный «Inter-VariableFont» проекта Tilda в кириллице не используется оригиналом (в нём нет кириллицы).
* Слайдер: геометрия оригинала — результат взаимодействия slick и скрипта масштабирования блока (`zoom = (W−120)/1200` при 1200–1679 px, `W/1200` от 1680). Масштаб воспроизведён тем же CSS; стартовая позиция ленты — «с нулевого слайда» (у оригинала она плавает из-за гонки скриптов).
* Один `<h1>`; порядок заголовков и тексты не менялись (в оригинале `h3` «Разработка сайтов на Тильде» стоит перед `h2` «Услуги» — оставлено как есть).
* Расхождения самого оригинала воспроизведены как есть: «754 проекта» (форма) и «более 350 …» (текст), ссылка *Tilda Experts*, написание «Тильде/Tilda».
* Внутренние ссылки на отсутствующие в копии страницы переписаны на абсолютные URL оригинала — «битых» внутренних ссылок нет.
* Репозиторий приватный, `NOINDEX` по умолчанию выключен: перед публикацией на тестовом домене включите `NOINDEX=1`.

## Известные различия с оригиналом

* Позиция слайдера отзывов в момент съёмки и состояние автоплея недетерминированы у обоих сайтов — в сравнении скриншотов этот блок проверяется по высоте (см. `reports/compare.md`, метка «динамич.»).
* Сглаживание текста (LCD vs. серое) зависит от слоя композиции: у Tilda тексты анимируемых блоков лежат в отдельных слоях. Для честного сравнения скриншоты снимаются с `--disable-lcd-text`.
