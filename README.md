# dviga-marketing — копия главной dviga.marketing без рантайма Tilda

Статическая копия **главной страницы** сайта агентства DVIGA (https://dviga.marketing/): тот же дизайн, тексты, изображения, адаптив и анимации, но вместо Tilda-скриптов и Tilda-стилей — собственный CSS (один файл + инлайн-критический) и JS (~10 КБ min, ~4 КБ gzip, без зависимостей).

> Область работ по решению заказчика: **только главная страница** (шапка, футер, все её попапы и формы входят). Остальные страницы сайта (/about, /cases, /services, /blog, …) в копию не входят; ссылки на них ведут на оригинальный сайт `https://dviga.marketing/...`. Англоязычная версия `en.dviga.marketing` не копируется. Полный список страниц Tilda-проекта — [reports/tilda-pages.md](reports/tilda-pages.md) (238 страниц).

## Быстрый старт

```bash
npm install
npm run build        # dist/ — готовая статика
npm run preview      # http://localhost:4173 (отдаёт dist/ со сжатием brotli/gzip)
npm run audit        # проверка: нет Tilda/запрещённых хостов, нет битых ссылок
```

Требования: Node ≥ 20. Для Playwright — `npx playwright install chromium`, для Lighthouse — установленный Google Chrome.

Переменные сборки: `SITE_URL` (по умолчанию `https://dviga.marketing`; canonical/og/sitemap/JSON-LD), `NOINDEX=1` (добавить `noindex`, пока копия не выведена в продакшен), `OUT` (каталог вывода), `CSS_MODE=link|async|inline` (доставка CSS; по умолчанию один блокирующий файл — см. ниже), `NO_CV=1` (отключить `content-visibility`).

## Как это устроено

```

        │   + Tilda MCP: head-код/JSON-LD страницы, проверка кастомного CSS проекта (он пуст), справка по формату блоков
        ▼

                    tools/lib/zero-layout.mjs   модель раскладки по брейкпоинтам 320/480/640/960/1200
                    tools/lib/sbs.mjs           keyframes пошаговых анимаций (hover/blockintoview)
                    tools/lib/components.mjs    cookie, слайдер отзывов, попапы, виджет, поиск
                    tools/lib/forms.mjs         формы (Zero-формы, t702, t708)
                    tools/lib/assets.mjs        <picture> AVIF/WebP + srcset, image-set() для фонов
                    tools/subset-fonts.mjs      урезание шрифтов до используемых символов
        ▼
dist/  index.html · assets/app.<hash>.css · assets/app.<hash>.js (+ чанки forms/slider) · img/ · video/ · fonts/ · _headers · robots.txt · sitemap.xml
```

### Раскладка Zero-блоков (ядро замены)
Tilda хранит для каждого элемента координаты на каждом брейкпоинте (`data-field-*-res-*`) и применяет их скриптом. Копия делает то же **на этапе сборки**:

* значения каскадируются между брейкпоинтами так же, как в `tilda-zero` (текущий → более широкие → базовый);
* оси `axisx/axisy`, контейнеры `grid`/`window`, `valign` артборда, `height_vh` переводятся в `left/top/translate/height` на CSS;
* масштаб между брейкпоинтами (`upscale=window`) — **только CSS**: `--s: tan(atan2(100cqw, <R>px))` + стандартное свойство `zoom`. Ширина берётся из `cqw` (ширина без полосы прокрутки; контейнер — `container-type:inline-size` у `<main>`/`<footer>`/попапов), поэтому JS на resize не нужен;
* `line-height` у текстов округляется до целых px (`round(1.2em, 1px)`), как это делает `t396__fixElementsLineHeights` в Tilda;
* CSS записей (типографика, цвета, hover) переписывается css-tree: селекторы Tilda → короткие классы, значения по умолчанию вынесены в `base.css`;
* секции вне экрана пропускаются браузером (`content-visibility:auto`) с точным `contain-intrinsic-block-size`, посчитанным из данных артборда — высота документа совпадает с оригиналом ещё до прокрутки;
* всё, что выступает за секции (артборды с `overflow:visible`), клипается на уровне `main`/`footer` — как у корневого контейнера Tilda (иначе на телефонах появляется горизонтальная прокрутка).

### Анимации
Полная таблица — [reports/animations.md](reports/animations.md). Кратко: появление (fadein) — CSS-transition + один `IntersectionObserver`; hover/blockintoview — `@keyframes`, сгенерированные при сборке, переключение классов в JS; scroll-шаги и «пин» (в т.ч. увеличение видео в хиро) — один rAF-обработчик, «fixed» реализован через `transform` (внутри контейнера `cqw` `position:fixed` ведёт себя иначе); счётчик «50+», слайдер, drag-лента, попапы — отдельный код. Поддержан `prefers-reduced-motion`. Тяжёлая инициализация откладывается до первого кадра (иначе принудительная раскладка попадает в TBT).

### Формы
Все 4 формы (две Zero-формы, «Рассчитайте стоимость» — многошаговая, виджет «Давайте подскажем») используют общий модуль `src/js/forms.js`: маска телефона `+7__________`, валидация (обязательные поля, email, телефон, согласие), состояния ошибки/успеха с теми же текстами, выбор файлов. Отправка:

```
POST /api/lead   (multipart/form-data)
  поля формы по их name (Name, Phone, Email, comment, Checkbox, File[] …)
  form  — идентификатор формы, page — URL страницы
```

## Развёртывание и кэширование
Статика из `dist/`. Файлы в `dist/assets/` имеют хеш в имени → отдавать с `Cache-Control: public, max-age=31536000, immutable`; HTML — `no-cache`. В `dist/_headers` лежит готовый конфиг (Cloudflare Pages / Netlify). Для nginx:

```nginx
location /assets/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
location = /index.html { add_header Cache-Control "no-cache"; }
gzip on; gzip_types text/css application/javascript image/svg+xml;   # лучше brotli on;
```

Включите сжатие на хостинге: замеры скорости сделаны с brotli (`tools/serve.mjs` сжимает как продакшен), без сжатия CSS (~300 КБ) заметно тормозит на медленных сетях. CSS доставляется одним блокирующим файлом (`CSS_MODE=link`): режимы `async`/`inline` проверены, но асинхронная загрузка вызывает вспышку «несобранной» вёрстки, а инлайн увеличивает HTML — выигрыша по Lighthouse нет.

## Что не перенесено и почему

* **Яндекс.Метрика, calltracking, tilda-stat, виджет Uploadcare/Upwidget** — по заданию (трекинг не переносится, телефон статичный).
* **Видео-шоурил хиро** `https://cp80604-bitrix-8.tw1.ru/showreel1.mp4` — **не удалось скачать**: хост не отвечает из сети, где выполнялась работа (оригинал на этом хосте у меня тоже показывает спиннер). Вместо ролика — чёрная скруглённая плашка; поведение (увеличение при прокрутке и «пин») работает. Подключить ролик: положить файл в `source-assets/showreel1.mp4`, выполнить `node tools/optimize-video.mjs && npm run build`. Остальные 8 видео кейсов перекодированы (H.264, 720p, без звука): 1.0–1.3 МБ → 0.1–0.3 МБ.
* **Полноэкранный fade-in страницы (блок t360)** — артефакт Tilda против вспышки неподготовленной вёрстки; в копии он задержал бы LCP.
* **Стрелки слайдера отзывов** — в оригинале есть в DOM, но скрыты (`display:none`); в копии кнопки тоже скрыты (`hidden`), слайдер листается автоплеем, свайпом и стрелками клавиатуры.
* **Поиск в шапке** (оригинал — виджет Tilda с индексом страниц сайта). Оверлей поиска повторяет вид; запрос открывает поиск Яндекса с `site:dviga.marketing` в новой вкладке (заглушка).
* **Скрытый SEO-блок со списком городов**: на главной такого блока нет (он на страницах услуг, которые в копию не входят) — переносить нечего.
* **Другие страницы Tilda-проекта** — вне области работ (список в `reports/tilda-pages.md`).
* **`<noscript>`:** без JS всё содержимое видно (анимации появления отключены), попапы и формы не работают.

## Решения по спорным местам

* Исходник — HTML опубликованной страницы (содержит полные `data-*` Zero-блоков); Tilda MCP использован для head-кода/JSON-LD страницы (воспроизведён как есть, логотип — локальный), проверки project CSS и справки по формату блоков; MCP-сервер ничего не менял в проекте. Данные из HTML и из браузера сверены: при расхождении побеждает то, что видно на экране.
* Шрифт Inter — те же woff2 (variable wght, latin+cyrillic), что отдаёт Google Fonts оригиналу; self-host, урезаны до реально используемых символов (67 → 43 КБ), `font-display:swap`, preload обоих файлов, fallback `Inter Fallback` с `size-adjust`. Файл `Inter-VariableFont_o.woff` из проекта Tilda не используется: в нём нет кириллицы, оригинал рисует текст Google-вариантом (проверено через CDP `getPlatformFontsForNode`).
* Слайдер: геометрия оригинала — результат взаимодействия slick и скрипта масштабирования блока (`zoom = (W−120)/1200` при 1200–1679 px, `W/1200` от 1680). Масштаб воспроизведён тем же CSS; стартовая позиция ленты — «с нулевого слайда» (у оригинала она плавает из-за гонки скриптов).
* Один `<h1>`; порядок заголовков и тексты не менялись (в оригинале `h3` «Разработка сайтов на Тильде» стоит перед `h2` «Услуги» — оставлено как есть).
* Расхождения самого оригинала воспроизведены как есть: «754 проекта» (форма) и «более 350 …» (текст), «Tilda Experts», написание «Тильде/Tilda».
* Внутренние ссылки на отсутствующие в копии страницы переписаны на абсолютные URL оригинала — «битых» внутренних ссылок нет (`npm run audit`).
* Три картинки слова «Кейсы» в эталоне измерены с 20-пиксельными превью (ленивая подгрузка Tilda не успевала) — в копии они имеют реальные пропорции, поэтому их высота в замерах анимаций отличается на 14–19 px; визуально секции совпадают.
* Репозиторий приватный; `NOINDEX` по умолчанию выключен — перед публикацией на тестовом домене включите `NOINDEX=1`.

## Известные различия с оригиналом

* Слайдер отзывов и видео недетерминированы (автоплей) — в сравнении скриншотов слайдер проверяется по высоте (метка «динамич.» в `reports/compare.md`), видео скрыты на обеих сторонах.
* Сглаживание текста у Tilda зависит от слоёв композиции; для честного сравнения скриншоты снимаются с `--disable-lcd-text`.
* Hero-ролик недоступен (см. выше).
